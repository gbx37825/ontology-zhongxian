# WXQ转Pipedream独立运行包

本包读取WXQ水动力模型JSON，转换成SuperLink输入表，完成预热和时变计算，导出Pipedream水位、流量CSV。它不接入HydroOS，不包含平台任务、MQTT、OPC UA或其他业务接口。

Pipedream完整库仍保留在pipedream_solver目录。新增的自适应预热放在wxq_pipedream/warmup.py，原库源码没有为这次改造而修改。

1.3.0起，预热和正式时变计算默认使用Numba加速版。兼容处理放在wxq_pipedream/backends.py，不修改原库，不改变闸门开度、闸流系数或正式计算步长。

## 安装

需要Python 3.11或3.12。使用uv，在本目录运行一次。

~~~bash
uv sync --python 3.11
~~~

也可以运行下面的命令。电脑有uv时会优先使用uv，没有时才使用venv和pip。

~~~bash
./run.sh setup
~~~

本包不捆绑解释器或虚拟环境。首次安装需要能访问Python包源。macOS以外的目标机仍需自行运行测试，Dockerfile保留，但本轮不宣称完成Docker部署验证。

## 跑自己的模型

把下列model.json替换成自己的WXQ模型路径。输出目录要使用新目录，程序不会覆盖非空目录中的旧结果。

~~~bash
./run.sh simulate /path/to/model.json outputs/run_001 \
  --warmup-config examples/自适应预热.json
~~~

输入应是包含baseData、initialData和timeControl的水动力模型，可以带一层模型名称。平台启动任务用的request.json不能直接作为水动力模型输入。

以上命令已默认使用Numba，无需额外配置。日志中的SOLVER行和运行摘要.json中的solver会显示实际求解器。需要对照普通版时，在同一命令后加上`--backend standard`，并使用另一个输出目录。

~~~bash
./run.sh simulate /path/to/model.json outputs/standard_001 \
  --warmup-config examples/自适应预热.json --backend standard
~~~

缺少Numba或设置了NUMBA_DISABLE_JIT=1时，加速入口会明确报错，不会暗中退回普通版。首次启动可能需要编译，编译耗时与水动力求稳耗时应分开理解。普通版仍可显式选择。

首次检查可以缩短正式计算，但仍执行预热。

~~~bash
./run.sh simulate /path/to/model.json outputs/smoke_001 \
  --warmup-config examples/自适应预热.json \
  --max-compute-steps 40
~~~

只检查预热时，将max-compute-steps设为0。只转换输入表时运行下面的命令。

~~~bash
./run.sh convert /path/to/model.json outputs/converted_001
~~~

## 预热步长在哪里改

直接修改examples/自适应预热.json。initial_dt是预热起始步长，单位为秒。填写30后，程序会根据检查结果自动增大步长；出现明显恶化或无效数值时，会回退到该批计算前的有效状态并减小步长。

临时改变起始步长，无需修改文件。

~~~bash
./run.sh simulate /path/to/model.json outputs/start_120 \
  --warmup-config examples/自适应预热.json \
  --warmup-dt 120
~~~

这不会将正式时变计算也改成120秒。正式步长默认读取模型的timeControl.calculateStep，需要覆盖时另传compute-dt。

~~~bash
./run.sh simulate /path/to/model.json outputs/start_60 \
  --warmup-config examples/自适应预热.json \
  --warmup-dt 60 --compute-dt 15
~~~

参数优先级为命令行覆盖、预热配置文件、模型initialData.options、程序默认值。模型中的timeStep对应起始步长，nStepMax对应总步数上限，thresholdZ对应水位变化门槛。ignoreSteadyState为true时，模型默认不预热；明确提供配置中的max_steps可以启用预热。

### 主要参数

| 参数 | 含义 |
| --- | --- |
| initial_dt | 起始预热步长，秒 |
| min_dt、max_dt | 自动调整允许的最小、最大步长，秒 |
| growth_factor、shrink_factor | 增大和减小步长时的倍率 |
| deterioration_factor | 相比上一批计算，误差程度超过此倍率时触发回退 |
| check_interval | 每多少个计算步检查一次 |
| consecutive_checks | 连续多少批满足条件后转入正常步长复核 |
| max_steps | 总尝试步数上限，包含回退掉的步数和末态复核 |
| max_wall_seconds | 预热推进的实际耗时上限；null表示不按耗时限制 |
| verification_steps | 留给正常计算步长复核的步数 |
| head_tolerance_m | 按正常步长折算的最大水位变化门槛 |
| flow_tolerance_m3s | 最大流量变化及节点稳态进出流量差的门槛 |
| storage_tolerance_m3s | 各非水位边界节点蓄量变化率绝对值之和的门槛 |
| balance_tolerance_m3s | 计入蓄量以后，局部及全网水量不闭合的门槛 |
| internal_method | 内部断面求解方式，默认lsq |
| num_iter | 每步水力迭代次数，默认1，预热复核与正式计算保持一致 |

总步数不够时，优先安排复核，实际复核数取verification_steps和max_steps中较小的一个。若未完成要求的复核步数，即使已检查的数值很小，也不会标成已收敛。max_steps为0时跳过预热。耗时上限按步检查，单个求解步执行期间无法立即中断。

## 水深和闸流系数

新运行入口不再统一把所有节点初猜水深改成7m。它沿用转换后的水位分布，默认数值启动水深下限为0.01m。

如果模型没有提供足够的初始水位资料，0.01m只用于避免数值完全干涸，不能当成现场水深。可以提供自己的SuperJunction初值表，或明确设置启动下限。

~~~bash
./run.sh simulate /path/to/model.json outputs/custom_initial \
  --warmup-config examples/自适应预热.json \
  --minimum-initial-depth 0.1
~~~

复现历史中线基线时，7m是显式试验条件，需要同时指定下面两个参数。它们不应照搬给其他工程。

~~~bash
--minimum-initial-depth 7 --all-superjunction-depth 7
~~~

minimum-initial-depth控制非水位边界连接点及内部节点的启动水深下限；all-superjunction-depth将连接点初猜水深统一设为指定值。水位边界仍按模型给定条件计算。superjunctions-csv可以提供按节点名称及ID对应的h_0表。

闸流系数默认来自模型。已有Pipedream专用率定系数时，可以额外传入gate-coefficients文件，格式是闸孔名称到C的JSON对象。程序检查名称与数值，不会把中线的系数自动套给另一条河网，也不改写原WXQ文件。

## 没算稳会怎样

预热未收敛也会继续正式仿真。输出里保留NOT_CONVERGED_CONTINUING标记，不能把它理解成稳定初态已经通过。

每次会生成下面的文件。

| 文件 | 查看内容 |
| --- | --- |
| 预热说明.md | 中文说明，列出检查值、门槛、超出量和最差位置 |
| 预热诊断.json | 完整参数、收敛状态、步数、耗时及量化诊断 |
| 预热收敛轨迹.csv | 每次检查的步长、误差程度、增大或回退动作 |
| 预热节点水量诊断.csv | 最后一次有效计算中，各节点的净入流、蓄量变化率和水量不闭合量 |
| 预热末态.json | 可恢复的求解器状态，并保留本次预热判断 |
| Pipedream原始输出.csv | 按原模型对象名称输出的水位、流量，附初态收敛标记 |
| 输出步汇总.csv | 每个记录时刻的全网数值范围 |
| 运行摘要.json | 计算是否完成、模型局限、预热状态和运行参数 |

水量不闭合量已扣除蓄量变化。蓄水增加或减少本身可以是正常非恒定流，预热求稳时还要额外检查这种变化是否足够小。各节点蓄量变化取绝对值后相加，避免一段蓄水、另一段放水互相抵消。

水位变化及按正式步长折算的流量变化，只用于数值收敛判断。它们无法代替与实测资料比较，更不保证每个工程自动达到半米精度。

若出现无法恢复的非有限水位或流量，正常求解器仍会报告数值异常。未收敛继续运行不意味着将无效数字当成有效结果。

## 当前范围

通用化覆盖预热配置、步长调整、水量检查和未收敛报告，不扩大原转换器支持的水工设施范围。

当前独立入口尚未求解转换器仅保留元数据中的水轮机，也未驱动泵、水轮机的时变控制曲线。模型含有这些内容时，会显示MODEL_WARNING，在运行摘要中将physical_model_complete设为false，并在CSV里标记model_coverage为INCOMPLETE。正常推进结束会记为COMPLETED_WITH_MODEL_LIMITATIONS，不能据此验收完整水电模型。

输出间隔必须是正式计算步长的整倍数。所有时刻均为从0开始的相对秒数。预热的伪时间不进入正式时间轴。

## 测试与打包

~~~bash
./run.sh test
./run.sh validate-quick --output outputs/quick_check
./run.sh pack
~~~

新的ZIP位于dist目录。打包只取程序、示例、测试、文档和许可证，不包含outputs、validation目录、真实工程模型、实测表或虚拟环境。

baseline目录保存的是继承的历史库及基线验证资料，不能把这些旧记录当成本版本的最新验收。validate-quick和validate-full显式使用standard，仍用于旧固定步长基线兼容检查；Numba默认入口另由tests中的测试覆盖。新包名称为WXQ_PipedreamNumba默认独立包_1.3.0.zip，旧1.2.0包不覆盖。

## 兼容旧固定步长预热

需要复现旧分档预算时，显式选择fixed模式。该模式保留旧方法，和本次自动调整步长的方式分别记录。

~~~bash
./run.sh simulate /path/to/model.json outputs/legacy_run \
  --backend standard --warmup-mode fixed --warmup-dt 15 \
  --warmup-checkpoints 40000 \
  --minimum-initial-depth 7 --all-superjunction-depth 7
~~~

Python调用可以使用wxq_pipedream导出的WarmupConfig和adaptive_warmup。直接调用旧的engine.stabilize方法仍是固定步长预热，不会悄悄替换其行为。

自适应模式恢复预热末态时，会核对原模型、转换后输入表、正式步长和求解器。换了模型、初始配置或闸流系数，不会混用旧缓存。新缓存采用v2格式，普通版与Numba版不交叉读取；切换后端时应重新预热。新缓存即使标记已收敛，恢复后也仍执行预热复核。旧v1缓存只在`--backend standard --warmup-mode fixed`兼容入口接受，不视为已验证初态。具体参数约定见Numba默认后端说明.md。
